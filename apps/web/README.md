# apps/web

One Next.js application, nine roles. See
[ADR 0004](../../docs/architecture/decisions/0004-single-web-app.md) for why it
is one app and not nine.

```bash
cp .env.example .env.local
pnpm --filter @janmaang/tokens build   # globals.css imports the generated file
pnpm --filter @janmaang/web dev        # http://localhost:3000
```

## Layout

```
src/
  proxy.ts                    Edge role guard. UX, not authorisation.
  app/
    (public)/                 Landing. Renders with no session.
    (auth)/login/             Sign in, plus the demo role picker.
    (app)/                    Session boundary — every role segment lives here.
      student/(shell)/        Dashboard, explorer, hubs, council, profile
      student/(focus)/        Collaboration wizard — full width, no sidebar
      faculty/ institute/ …   Still stubs.
    api/council/              Council turn, verdict and speech. See ADR 0005.
  components/                 Icon set, primitives, the app shell
  features/student/data.ts    Presentation fixtures. Replaced by API calls.
  lib/auth/                   Roles, session tokens, the directory seam
  lib/council/                Council orchestration — pure, framework-free
  lib/i18n/                   English and Hindi strings
```

The two route groups under `student/` both keep the `/student/` URL prefix,
which is what the proxy's segment guard reads. They differ only in chrome.

## Authentication

`lib/auth/directory.ts` is a stand-in. `services/api`'s auth module is a stub
today, so credentials are checked against a fixed list of demo personas — one
per role, all sharing the password `janmaang`. **Never deploy it anywhere
reachable from the internet.**

Sessions are an HMAC-signed, `HttpOnly` cookie (`lib/auth/session.ts`), signed
with `AUTH_SECRET`. Signing means a visitor cannot edit their own role into the
cookie. It does not mean the role is trusted: **the API authorises every read
and write**, and `proxy.ts` only shapes navigation.

Replacing the seam is one function — point `authenticate` at
`${NEXT_PUBLIC_API_URL}/auth/login`. Nothing else imports the demo list.

## Design tokens

Tailwind v4 is CSS-first: there is no `tailwind.config.ts`. The theme is the
`@theme` block generated by `@janmaang/tokens` from `tokens.json`, so every
token is a utility class — `--color-impact-wash` is `bg-impact-wash`. Add a
colour there, not here, and never write a brand hex in a component.

One trap worth knowing: token names land in Tailwind's own namespaces. Naming a
spacing token `--spacing-md` silently redefines `max-w-md`. That is why the
`space` scale is emitted as plain `--jm-space-*` instead.
